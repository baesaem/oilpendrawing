# 오일펜 드로잉 앱 · 시안 제안서

사진(컬러/흑백)을 AI로 **오일펜 드로잉**으로 바꿔 주는 웹 앱의 화면 시안과 기술 구성안입니다.
화면 목업 원본은 `design/` 폴더에 있습니다.

---

## 1. 한 줄 정의

> 사진 한 장과 (선택) 견본 그림 한 장을 넣고, 숙련도·강도·색·빛 방향·밝기를 조절해
> 내 API 키로 오일펜 드로잉을 생성·비교·저장하는 도구.

## 2. 사용 흐름

1. **첫 실행** — 이미지 생성 제공사 선택 → API 키 입력 → 연결 확인 → 저장 (브라우저에만 저장)
2. **입력** — 원본 사진 업로드 (컬러/흑백 자동 감지, "흑백으로 변환하여 입력" 토글)
3. **견본(선택)** — 참고할 펜 드로잉 업로드 + 견본 반영도(0~100%)
4. **표현 설정** — 숙련도 / 강도 / 색 표현 / 빛의 방향 / 밝기 / 대비
5. **생성** — 약 30초 → 원본·결과 분할 비교 → PNG 저장, 같은 설정으로 다시, 이력 탐색

## 3. 화면 구성 (기본안 "아틀리에")

| 화면 | 프레임 | 내용 |
|---|---|---|
| 데스크톱 작업 화면 | 1440×900 | 3열: 입력(320) · 결과 비교(가변) · 표현 설정(360) |
| 모바일 | 390×844 | 결과 미리보기 → 원본/견본 → 설정 순으로 세로 배치, 하단 고정 생성 버튼 |
| 첫 실행 · API 키 | 720×640 | 제공사 선택, 키 입력(마스킹), Claude 키(선택), 기기 기억 체크 |

### 시각 방향
- **톤**: 종이(`#f4eee3`)·패널(`#ede5d6`)·잉크(`#2b2420`)·포인트 시에나(`#b5532a`, 오일펜 잉크색)
- **서체**: 헤드라인 Nanum Myeongjo(명조), 본문 Noto Sans KR
- **모티프**: 결과 미리보기의 해칭·교차 해칭 질감이 그대로 브랜드 요소가 됨

### 대안 (저해상 스케치)
- **B. 다크 스튜디오** — 전체 화면 캔버스 + 떠 있는 패널. 몰입감 높음, 초보자에겐 조작이 숨어 보임.
- **C. 단계형 위저드** — 원본 → 견본 → 표현 → 결과, 한 화면에 한 결정. 헷갈릴 게 없지만 설정 바꿔 재생성하는 반복이 느림.

## 4. 표현 파라미터 정의

| 파라미터 | UI | 범위 | 프롬프트/처리 매핑 |
|---|---|---|---|
| 숙련도 | 세그먼트 3단 | 초급 / 중급 / 상급 | 아래 표 |
| 강도 | 슬라이더 | 0~100 | 선 밀도·필압·겹침 횟수 서술 (예: 70 → "dense confident strokes, heavy pressure") |
| 색 표현 | 카드 3개 | 컬러 / 흑백 / 세피아 | 컬러: 제한된 팔레트의 유색 오일펜 · 흑백: 검정 단색 · 세피아: 갈색 단색 |
| 빛의 방향 | 8방향 원판 | 좌상단 등 8개 | "key light from upper-left; shadows fall lower-right; hatching follows form away from light" |
| 밝기 | 중앙 기준 슬라이더 | -50~+50 | 결과 이미지 후처리(CSS/캔버스 필터) + 프롬프트의 종이 노출 정도 |
| 대비 | 중앙 기준 슬라이더 | -50~+50 | 후처리 + "deep blacks vs. untouched paper" 서술 |
| 견본 반영도 | 슬라이더 | 0~100% | 견본 이미지를 참조 이미지로 첨부하고, 반영도에 따라 스타일 서술 비중 조절 |

### 숙련도 3단계

| 단계 | 선 | 명암 | 디테일 |
|---|---|---|---|
| 초급 | 굵고 적은 윤곽선, 큰 형태 위주 | 한 방향 단순 해칭 1~2단계 | 질감 생략, 배경 최소 |
| 중급 | 윤곽 + 내부 형태선 | 한 방향 해칭으로 중간톤 3~4단계 | 주요 질감만 |
| 상급 | 얇고 겹치는 선, 강약 변화 | 교차 해칭, 반사광·그림자 경계 | 표면 질감·배경까지 세밀 |

## 5. 기술 구성안

### 5.1 아키텍처 (권장: 서버 없는 정적 웹 앱)

```
브라우저 (React + Vite, 정적 배포: GitHub Pages / Vercel)
 ├─ 입력 처리: 리사이즈·흑백 변환·EXIF 회전 (Canvas API)
 ├─ 프롬프트 빌더: 파라미터 → 드로잉 지시문 (표 4 매핑)
 ├─ [선택] Claude 비전: 견본 분석 → 지시문 정교화 (사용자 Claude 키)
 ├─ 이미지 생성 API 호출 (사용자 키, 브라우저 → 제공사 직접)
 ├─ 후처리: 밝기·대비·종이 질감 오버레이 (Canvas)
 └─ 저장: 결과·설정 이력 → IndexedDB, API 키 → localStorage(선택)
```

- **BYOK(내 키 사용)**: 키는 브라우저에만 저장. 서버가 없으니 키 유출 표면이 없음.
- **제공사 추상화**: `ImageProvider` 인터페이스 하나(`generate(input, reference?, prompt, options)`)로 OpenAI 이미지·Google Gemini 이미지·Stability AI를 갈아 끼움. 최신 모델 ID는 구현 시점에 각 제공사 문서에서 확인.
- **브라우저 직접 호출이 CORS로 막히는 제공사**가 있으면 그 제공사만 얇은 프록시(Cloudflare Worker)로 우회. 키는 요청 헤더로만 통과, 저장 안 함.

### 5.2 견본 이미지 활용 (2단계 파이프라인, 선택)

1. **분석** — Claude(`claude-opus-5`, 비전)에 견본 + 원본을 보내 "선 밀도, 해칭 각도, 톤 단계 수, 종이 노출 비율"을 구조화 JSON으로 추출 (`output_config.format`).
2. **생성** — 추출값을 프롬프트 빌더에 합쳐 이미지 생성 API에 견본을 참조 이미지로 첨부.

Claude 키가 없으면 1단계를 건너뛰고 견본을 참조 이미지로만 첨부합니다.

### 5.3 저장 데이터

```ts
type Drawing = {
  id: string; createdAt: number;
  input: Blob; reference?: Blob; result: Blob;
  params: { level: '초급'|'중급'|'상급'; intensity: number; color: 'color'|'mono'|'sepia';
            light: 'N'|'NE'|'E'|'SE'|'S'|'SW'|'W'|'NW'; brightness: number; contrast: number;
            referenceWeight: number; };
  provider: string; prompt: string;
};
```

## 6. MVP 범위 제안

**1차 (2~3주)**: 데스크톱 화면 · OpenAI 이미지 1개 제공사 · 견본 첨부(분석 없이) · 6개 파라미터 · PNG 저장 · 이력 5개
**2차**: 모바일 레이아웃 · 제공사 2개 추가 · Claude 견본 분석 · 밝기/대비 실시간 후처리 미리보기
**3차**: 일괄 변환, 프리셋 저장/공유, 인쇄용 고해상 출력

## 7. 열려 있는 결정

- 기본안(아틀리에) vs 대안 B/C 중 방향 선택
- 첫 지원 제공사 (OpenAI 이미지 / Gemini 이미지 / Stability)
- 정적 앱만으로 갈지, 프록시 서버를 처음부터 둘지
